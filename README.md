## 项目说明

基于 TI MSPM0G3507 的 **智能小车控制工程**，采用 **app-bsp-middleware-core 四层架构**。

当前 1.4-dev 分支已实现：
- **JY62 陀螺仪驱动** — 六轴姿态数据 UART 状态机解析（角速度/角度/加速度）
- **陀螺仪航向锁** — 比例纠偏控制器（deadband + 限幅）
- **陀螺仪任务调度** — 原地转向 + 距离驱动状态机
- **DMA 循环接收** — UART2 + DMA 乒乓缓冲，零中断逐字回调
- **巡线算法** — 非线性 PD 巡线控制（查表法衰减 + 差速转向）
- **灰度传感器** — 8 路数字灰度传感器读取（多路复用 + GPIO 直接读取）


- **UART 通信** — 环形缓冲 + 中断收发
- **PI 速度闭环** — 增量式离散 PI 控制器（deadband + 低通滤波）
- **编码器测速** — 双路正交编码器 2x 解码（GPIO 中断 + ISR 内实时计数）
- **电机驱动** — TB6612 双路 H 桥 PWM 控制（正反转 + 占空比）
- **按键控制** — 单击检测状态机
- **OLED 显示** — SSD1306 驱动（软件 SPI，含 6x12 / 8x16 ASCII 字库），显示左右轮目标/实际速度
- **LED 指示** — GPIO 控制（亮、灭、翻转、闪烁）
- **10ms 定时器** — 周期性定时器 ISR（回调模式）
- **延时服务** — SysTick 精密延时（毫秒 / 微秒）
- **四层架构** — app / bsp / middleware / core 分层落地，包含完整编码规范

## 分层架构与开发规范

本项目采用 **app / bsp / middleware / core** 四层架构，各层职责和依赖关系如下：

| 层 | 职责 | 可包含的依赖 | 当前模块 |
|----|------|-------------|---------|
| **app/** | 应用逻辑：主循环、状态机、控制算法 | middleware/、bsp/、core/ | `main.c`（入口）、`app_control`（PI 控制 + 显示调度） |
| **middleware/** | 协议/融合层：传感器数据处理、通信协议、算法抽象 | bsp/、core/ | `mid_oled`（SSD1306 驱动）、`mid_line_track`（巡线算法）、`mid_k230`（K230 协议解析） |
| **bsp/** | 板级驱动：外设封装（GPIO、UART、PWM、ADC 等） | core/（`ti_msp_dl_config.h`）及标准库 | `bsp_delay`、`bsp_led`、`bsp_motor`、`bsp_encoder`、`bsp_grayscale`、`bsp_key`、`bsp_timer`、`bsp_uart` |
| **core/** | 启动文件、SysConfig 生成代码、链接脚本 | 不包含上层任何文件 | `ti_msp_dl_config.c/h` |

### 关键规范

**1. include 依赖方向 — 单向，禁止反向或跨层循环**

- `bsp/` 模块仅包含 `"ti_msp_dl_config.h"` 和标准库头文件，不包含同层其他 BSP 模块
- `middleware/` 可包含 `bsp/*.h`，不包含 `app/*.h`
- `app/` 可包含 `middleware/*.h` 和 `bsp/*.h`
- 统一使用 `<stdint.h>` 的 `uint8_t`/`uint16_t`/`uint32_t` 等标准类型，不使用自定义别名

**2. 中断所有权 — BSP 拥有 ISR，app 注册回调**

- 外设 ISR 定义在对应的 `bsp/xxx.c` 中，不在 `main.c` 中定义
- BSP 模块提供回调注册接口（如 `Timer_RegisterCallback(func)`）
- `app/main.c` 在初始化时向 BSP 注册回调
- ISR 内仅做：清中断标志 → 调回调 → 设 volatile 状态变量，不做复杂计算

**3. SysConfig 是外设配置的唯一真实来源**

- 所有引脚、外设实例、时钟、DMA 均在 `.syscfg` 中定义
- 应用代码**仅使用**生成的宏（`GPIO_LED_PORT`、`UART_0_INST` 等），绝不硬编码寄存器地址或引脚号
- 新增外设时先修改 `.syscfg`，构建生成 `ti_msp_dl_config.c/h` 后再编写应用代码
- 手写代码绝不直接修改生成的 `ti_msp_dl_config.c/h`

### 蓝牙指令集扩展规范

> **已移除。** `mid_ble.c/h` 已从项目中删除，BLE 桥接功能不再使用。UART1 现专用于 K230 视觉模块通信。如需恢复，参考 git 历史 `e555f77` 之前的版本。

新增 middle 或 bsp 的 `.c` 文件必须手动加入 Keil 项目对应 Group。

## 编码规范

### 1. 通用约定

| 项目 | 规则 |
|------|------|
| 缩进 | 4 空格，不使用 Tab |
| 语言标准 | C99 |
| 整数类型 | 统一使用 `<stdint.h>` 标准类型（`uint8_t`、`uint16_t`、`uint32_t`、`int32_t` 等） |
| 布尔类型 | 使用 `<stdbool.h>` 的 `true` / `false` |
| 自定义别名 | 禁止 — 不使用 `u8`、`u16`、`u32` 等非标准缩写 |
| 大括号风格 | K&R 风格（函数定义换行，控制语句不换行） |

### 2. 命名规范

| 类别 | 格式 | 示例 |
|------|------|------|
| 文件名 | `层_模块.c` / `层_模块.h` | `bsp_led.c`, `mid_oled.c`, `app_control.c` |
| 公开函数 | `层_模块_动作()` | `BSP_LED_Init()`, `MID_OLED_DisplayString()` |
| 内部 / `static` 函数 | `模块_动作()`（小写 + 下划线） | `led_set_gpio()`, `uart_rx_isr()` |
| SysConfig 生成的宏 | **直接使用**，不重命名、不 alias | `GPIO_LED_PORT`, `UART_0_INST` |
| 用户自定义宏 | `大写_下划线` | `LINE_SENSOR_THRESHOLD`, `OLED_WIDTH` |
| `static` 全局变量 | `s_` 前缀 | `s_callback`, `s_initialized` |
| 全局变量（极少使用） | `g_` 前缀 | `g_system_state` |
| 回调类型 `typedef` | `层_模块_回调_t` | `bsp_timer_callback_t` |
| 枚举常量 | `大写_下划线` | `CONTROL_STATE_IDLE`, `SENSOR_LEFT` |
| 枚举类型 `typedef` | `层_模块_枚举_t` | `bsp_led_color_t`, `app_state_t` |

### 3. 模块接口规范

每个 BSP 模块遵循统一的接口模式：

| 接口 | 说明 | 是否必须 |
|------|------|---------|
| `BSP_<Module>_Init(void)` | 初始化外设，返回 `bool`（true=成功） | **必须** |
| `BSP_<Module>_RegisterCallback(cb)` | 注册中断回调 | 按需 |
| `BSP_<Module>_Read()` / `_Write()` / `_Control()` | 功能函数 | 按需 |

Middleware 模块前缀改为 `MID_`，App 模块前缀改为 `APP_`。

### 4. 文件组织模板

```c
// ==================== bsp_xxx.h ====================
#ifndef BSP_XXX_H
#define BSP_XXX_H

#include <stdint.h>
#include <stdbool.h>

// Init
bool BSP_Xxx_Init(void);

// Callback registration (if needed)
typedef void (*bsp_xxx_callback_t)(void);
void BSP_Xxx_RegisterCallback(bsp_xxx_callback_t cb);

// Functional API
void BSP_Xxx_Action(void);

#endif
```

```c
// ==================== bsp_xxx.c ====================
#include "bsp_xxx.h"
#include "ti_msp_dl_config.h"

// Internal constants
#define XXX_FOO  100

// Static state
static bsp_xxx_callback_t s_callback = NULL;
static volatile bool s_event_flag = false;

// Internal helper
static void xxx_do_something(void) {
    // ...
}

// Public API
bool BSP_Xxx_Init(void) {
    // DL_ 初始化调用，使用 SysConfig 生成的宏
    return true;
}

void BSP_Xxx_RegisterCallback(bsp_xxx_callback_t cb) {
    s_callback = cb;
}

// ISR (if this module owns an interrupt)
void XXX_IRQHandler(void) {
    // 1. Clear interrupt flag using SysConfig macro
    // 2. Call callback
    // 3. Set volatile state variable
    if (s_callback) {
        s_callback();
    }
}
```

### 6. ISR 规范

| 规则 | 说明 |
|------|------|
| 归属 | ISR 函数体定义在对应的 `bsp_xxx.c` 中，**不在** `main.c` |
| 内部行为 | **仅做三件事**：清中断标志 → 调用回调 → 设置 `volatile` 状态变量 |
| 复杂计算 | ISR 内不做复杂计算，复杂逻辑在回调或主循环中处理 |
| 回调注册 | BSP 模块提供 `BSP_Xxx_RegisterCallback()` 供 app 层注册 |
| 共享变量 | ISR 和主循环共享的变量必须加 `volatile`，如 `static volatile bool s_flag;` |

> **编码器例外：** `bsp_encoder.c` 的 `GROUP1_IRQHandler` 不遵循回调模式，而是直接在 ISR 内做 2x 正交解码并累加计数，通过 `GetCount` / `ResetCount` API 暴露给 app 层。这是因为编码器脉冲必须在每个边沿实时处理，无法延迟到回调。

#### 回调模式示例

```c

```

### 二、整体方案

#### 2.1 机械结构

**270° 舵机 + 齿轮齿条**

- **摆杆倾斜调节**：270° 舵机输出轴安装小齿轮（pinion），齿轮与竖直齿条（rack）啮合。舵机旋转驱动齿条竖直升降，齿条顶端顶住摆杆末端底面，带动摆杆绕左侧铰链俯仰。
- **固定端**：摆杆左侧合页安装于小车左支撑台（高度 ≥ 5cm），为唯一旋转支点。
- **执行端**：摆杆右端下方竖直安装齿条+导向槽，齿条顶端贴合摆杆底面。舵机通过支架固定于小车平台，输出轴齿轮与齿条啮合。
- **导向与限位**：齿条在导向槽内竖直滑动，上下行程由机械限位 + 程序软限位保护。
- **重力预紧**：摆杆自重始终压在齿条顶端，齿轮-齿条啮合间隙被单向受力消除，无回差影响。

#### 2.2 运动转换原理

舵机接收 PWM 控制信号，输出轴驱动小齿轮旋转，齿轮-齿条啮合将旋转运动转化为齿条竖直直线位移。映射关系为 **线性**：Δh = r × θ（r 为齿轮分度圆半径，θ 为舵机转角）：
- 齿条 **上升** → 摆杆右端抬高 → 凹槽向左倾斜 → 钢球向负方向(-cm)滑动
- 齿条 **下降** → 摆杆右端下沉 → 凹槽向右倾斜 → 钢球向正方向(+cm)滑动

270° 舵机提供比标准 180° 舵机多 50% 的转角行程，在同等齿轮半径下获得更大的竖直行程。以 r = 10mm 齿轮为例，270° 对应齿条行程 ≈ 47mm，覆盖摆杆末端 ±10° 倾角需求。控制接口为单线 PWM，MSPM0G3507 定时器直接输出，无需专用驱动器。

#### 2.5 闭环控制流程

```
K230视觉采集 → UART发送钢球坐标 → MSPM0接收
    ↓
偏差计算: error = ball_x - target_x
    ↓
位置 PID: Kp·error + Kd·derivative + Ki·integral
    ↓
动态前馈: Kff_accel × 车体加速度 + Kff_curve × 弯道曲率
    ↓
输出限幅 → 舵角 = PID输出 / (r × 线性系数) → PWM占空比 → 舵机
    ↓
齿轮齿条升降 → 摆杆倾角变化 → 钢球滑动 → K230再次采集 (闭环)
```

**前馈补偿来源**：
- 车体纵向加速度 ← 编码器速度差分（`Δspeed / 10ms`）
- 过弯离心力方向 ← 循线误差符号（`MID_LineTrack_GetError()`）

#### 2.6 定点切换逻辑

```
IDLE → MOVE_TO_P5 (target=+5cm, 到达即折返, |error|≤1cm)
     → MOVE_TO_M5 (target=-5cm, 到达并稳定, |error|≤1cm)
     → DONE (上报总耗时 ≤5s)
```

#### 2.8 K230 ↔ MSPM0 通信协议

- **物理层**：UART1，115200bps，8N1。K230 TX(11) → MSPM0 PB7(RX)
- **帧格式（三字段，ASCII 文本，`,` 分隔，`\r\n` 结尾）**：

| 场景 | 帧 | 示例 |
|------|-----|------|
| 检测到球 | `X:%+.1f,T:%u,D:1\r\n` | `X:+35.0,T:12345,D:1\r\n` |
| 未检测到 | `X:--,T:%u,D:0\r\n` | `X:--,T:12346,D:0\r\n` |

| 字段 | 格式 | 含义 |
|------|------|------|
| `X` | `%+.1f`（mm，精度 0.1mm）或 `--` | 钢球在水管凹槽中的一维位置（K230 `cx_to_mm()` 输出）。中心 O=0，正方向为正。`--` 表示未检测到球 |
| `T` | `%u`（uint32，ms） | K230 系统时钟 `time.ticks_ms()`，帧生成时刻打戳。MSPM0 端用相邻帧 T 差值做微分，不受帧率波动影响 |
| `D` | `0` 或 `1` | 检测标志。D=1 → X 有效；D=0 → X=`--`，MSPM0 应暂停 PID 输出、保持当前舵角，防止用过期坐标继续控制 |

> ⚠️ **K230 坐标符号反转（2026-07-30 确认）**：K230 端 `cx_to_mm()` 输出的 X 字段正负号与物理坐标系**相反**（球在 +cm 时发送负值，球在 -cm 时发送正值）。MSPM0 端 `mid_k230.c` 解析时已做取反处理（`s_ball_position = -pos`），因此 `MID_K230_GetPosition()` 返回的是**已修正的物理坐标**。若更换 K230 固件或重新标定 `cx_to_mm()`，需重新确认符号方向。

- **发送频率**：每帧推理后立即发送，持续最大帧率（实测约 33fps）
- **MSPM0 端解析**：`middleware/mid_k230.c`，主循环非阻塞轮询 `BSP_UART`。提供 API：`GetPosition()` / `IsDetected()` / `GetTimestamp()`（K230 时间戳）/ `GetLastUpdate()`（本地 tick 超时检测）

##### 2.9.2 参数需求

K230 每帧通过 UART 向 MSPM0 发送一帧，包含以下字段：

| 参数 | 帧中字段 | 类型 | 说明 |
|------|----------|------|------|
| X 坐标 | `X:+35.0` 或 `X:--` | float mm / `--` | 球在水管凹槽中的一维位置（中心 O=0）。`--` 表示未检测到球 |
| 时间戳 | `T:12345` | uint32，ms | K230 `time.ticks_ms()`，帧生成时刻打戳。MSPM0 端按相邻帧 T 差值做微分，不受帧率波动影响 |
| 检测状态 | `D:1` 或 `D:0` | uint8，0/1 | 球是否被检测到。D=0 时 X 必须为 `--`，MSPM0 应暂停 PID 输出、保持当前舵角；D=1 时 X 有效 |

**完整帧格式**：

| 场景 | 帧 | 示例 |
|------|-----|------|
| 检测到球 | `X:%+.1f,T:%u,D:1\r\n` | `X:+35.0,T:12345,D:1\r\n` |
| 未检测到 | `X:--,T:%u,D:0\r\n` | `X:--,T:12346,D:0\r\n` |

> K230 端 `cx_to_mm()` 输出单位为 mm，`%+.1f` 格式化为 1 位小数（精度 0.1mm）。MSPM0 端 `GetPosition()` 返回原始 float mm 值。

##### 2.9.3 暂定方案：比例法

> 目标：通过 YOLOv5n 同时检测"小球"和"水管"两个 object，利用几何比例关系从像素坐标反算钢珠一维物理坐标（cm），而非让模型直接回归坐标。

**方案理由**：比例是几何运算而非学习到的，泛化性好。关键位置（0cm、±5cm 等）的标注仅用于拟合和验证比例→cm 映射，不用于训练 YOLO 回归坐标。

**步骤：**

1. **管道 bbox 冻结为常量参考框**
   摄像头固定于摆杆正上方俯拍，管道与相机的相对位置不变。取前 N 帧管道 bbox 的中位数作为固定参考框，后续不再更新。此举消除管道 bbox 帧间抖动对 ratio 分母的影响——水管细长（约 25cm×2cm），YOLO 对这种极端长宽比物体的 bbox 易抖动。

2. **球 x_center 作为像素 X 坐标**
   直接使用 YOLO 检测框的 `bbox.x_center`，bbox 中心比边缘稳定，精度一般到 1~2 pixel。

3. **比例计算**
   ```
   ratio = (ball_x_center - pipe_x_left) / pipe_width    // 范围 0~1
   ```
   其中 `pipe_x_left` 和 `pipe_width` 来自步骤 1 冻结的管道参考框。

4. **比例 → 物理坐标映射**
   用已标注的关键位置（0cm、±5cm 等）做最小二乘线性拟合：
   ```
   ball_cm = a × ratio + b
   ```
   至少两个标注点即可解出 a、b，点越多拟合越准。系数 a、b 写入 K230 固件，坐标转换在 K230 端完成后再发 UART。

5. **边缘处理**
   若摄像头 FOV 不覆盖管道全长（±12cm），ratio 0~1 仅对应可见段。拟合时只用可见范围内的标注点，比例映射仍保持线性。球滚出视野边缘时 ratio clip 到 0 或 1。

**备注：**
- 管道超出 FOV 时 ratio 0~1 仅对应可见段，拟合时只用可见范围标注点，线性仍成立
- 球滚出视野时 ratio clip 到 0 或 1，MSP 端收到 D=1 但 X≈±limit 时按"球靠边界"而非"球丢失"处理
- 若后续发现线性度不够（镜头畸变大），可升级为多项式拟合 `ball_cm = a₀ + a₁·r + a₂·r² + …`

##### 2.9.4 端到端延时链

33fps = 30ms/帧，延时从 K230 拍到球到 MSP 输出 PWM 的完整链路：

```
摄像头曝光    K230推理    UART串行化    MSP接收/解析    PID计算    PWM更新    舵机响应    齿条传动    球开始移动
   |------|    |------|    |------|     |---------|     |-----|    |-----|    |------|    |------|    |------|
   ~5ms        ~15ms       ~1ms          ~0.5ms         ~0.1ms    ~0.05ms    ~10ms       ~2ms        ~5ms
```

| 环节 | 延时 | 占比 | 可否优化 |
|------|------|------|---------|
| K230 曝光 | 3~8ms | 17% | 降分辨率 / ROI 裁切 |
| K230 推理 | 10~20ms | **33%** | **最大瓶颈**。换更轻模型、缩小搜索区域 |
| UART 串行化 | ~1.7ms | 4% | 20 字节 @115200，基本忽略 |
| MSP 接收+解析 | <0.5ms | 1% | DMA 接收，忽略 |
| PID 计算 | <0.1ms | <1% | 忽略 |
| 舵机响应 | 8~15ms | **25%** | **第二大瓶颈**。数字舵机内部 300Hz PID，60°阶跃约 100ms，小角度 10~20ms |
| 齿条传动+球惯性 | 5~20ms | 19% | 机械减速 15.6:1 + 静摩擦死区，物理限制 |

**总延时：**

```
感知延时（帧间隔）    ≤30ms
UART + MSP              ≈2ms
舵机小角度响应         ≈15ms
齿条 + 球惯性          ≈10ms
────────────────────────────
合计                   ≈45ms
```

##### 2.9.5 控制环影响评估

| 指标 | 数值 | 说明 |
|------|------|------|
| 感知帧率 | 33fps | 帧间隔 30ms |
| 总纯延时 | ~45ms | K230 感知 → 球开始响应 |
| 延时/采样周期 | ~1.5 个周期 | 在 33Hz 控制环下 |
| 30ms 内球位移 | ~0.25mm | 0.55m/s² 加速度下，远小于 ±1cm 容差 |
| 机械低通 | 15.6:1 减速 | 高频扰动被过滤 |

**结论：33fps 够用。** 机械系统本身就是低通滤波器，球不可能在单帧间隔内突变。瓶颈不在帧率，在纯延时。

##### 2.9.6 控制对策

1. **微分先行 PID**（derivative-on-measurement）：微分仅作用于测量值，避免设定值跳变引起微分冲击
2. **KD 保守起步**：KD = KP/5 ~ KP/8，延时大时微分不宜过强
3. **积分限幅 + anti-windup**：死区以下积分停止累积，防止静摩擦导致的 windup
4. **K230 帧带时间戳**：每帧附加 ms 级时间戳，MSP 端按实际帧间隔做微分，不受帧率波动影响
5. **无需固定帧率**：MSP 端收到即处理，多余帧丢帧策略优于等待固定间隔

### 三、测试方案初步

> 目标：获取系统传递函数关键参数，为 PID 调参提供定量依据。

#### 3.1 测试条件

- K230 稳定输出钢珠坐标
- MSP 端预留 BLE 数据记录链路：`!BALL ON` 开始以 100Hz 发送 `<tick>,<ball_cm>`，`!BALL OFF` 停止
- 摆杆倾角通过舵机 PWM 控制（需先完成 3.5 齿轮齿条标定）

#### 3.2 静摩擦死区测试

| 项目 | 内容 |
|------|------|
| **目的** | 找出钢珠从静止开始移动的**最小倾角** θ_min |
| **方法** | 摆杆水平，球置中心 O。倾角从 0° 开始，每次增加约 0.05°~0.1°，保持 3s，观察 K230 坐标是否变化 |
| **判据** | 球开始移动的最小倾角 = 死区上限 |
| **用途** | 死区以下 PID 输出被静摩擦吃掉，积分项持续累积 → windup。用于设定控制死区 + anti-windup 限幅 |

#### 3.3 阶跃响应测试

| 项目 | 内容 |
|------|------|
| **目的** | 获取系统增益 K 和摩擦力等效减速度 |
| **方法** | 球置中心 O。摆杆阶跃到指定倾角 θ，BLE 全程记录 `<tick>,<ball_cm>`（100Hz），直到球滚到 ±12cm 尽头或 3s 超时 |
| **分组** | θ₁ = θ_min + 0.2°（小阶跃）；θ₂ = 0.8°（中等）；θ₃ = 1.5°（大阶跃）。各重复 3 次 |

**后处理**（Python/MATLAB）：

```
1. 位置差分 → 速度 v = gradient(x, 0.01)
               加速度 a = gradient(v, 0.01)
2. 取球启动后前 200ms 的平均加速度 a_mean
3. 系统增益 K = a_mean / θ         (单位: (m/s²)/deg)
4. 摩擦等效减速度 a_fric = g·sin(θ) - a_mean
5. 纯延时 = 阶跃时刻 → 球开始响应的时间差
```

| 输出参数 | 用途 |
|----------|------|
| θ_min | 控制死区下限 + 积分 anti-windup 阈值 |
| K (增益) | 外环 PID 的 Kp 初值估算 |
| a_fric | 评估凹槽顺滑度；若明显偏大（>0.05m/s²），水管内壁可能需要打磨或涂润滑 |
| 纯延时 | K230 帧延迟 + UART 通信延迟的实测值，用于判定外环控制频率上限 |

#### 3.4 后续可选：频率扫描

阶跃响应完成后，可进一步用小幅度正弦扫频（θ = θ_min + A·sin(ωt)，A≈0.3°，ω 从 1Hz 扫到 10Hz），观察钢珠跟踪幅度衰减，确定系统带宽。此步骤为可选优化，不阻塞初步调参。

#### 3.5 齿轮齿条标定

> 目的：建立舵机 PWM 占空比与摆杆末端竖直位移之间的定量关系，为控制算法提供线性映射系数。

| 项目 | 内容 |
|------|------|
| **目的** | 标定 PWM 占空比 → 齿条位移 → 摆杆倾角的线性系数 |
| **方法** | 舵机从 0° 开始，每次增加 10°，用量角器/倾角仪测量摆杆实际倾角，或用卡尺测量齿条顶端高度。记录 PWM 值、舵机转角、齿条高度、摆杆倾角四列数据 |
| **分组** | 0° → 270°，步长 10°，共 28 个采样点。正反行程各 3 次（检测回差） |
| **判据** | ① 线性度 R² > 0.99（齿轮齿条理论上是纯线性）；② 正反行程高度差 < 0.2mm（齿轮啮合回差） |
| **用途** | 拟合斜率 k = Δh/ΔPWM，写入 `bsp_servo.c` 作为 PWM→高度映射常数。外环 PID 输出期望倾角后，直接按线性关系换算为 PWM 值 |

**后处理：**

```
1. 正行程拟合: h_forward = k_forward × PWM + b_forward
2. 反行程拟合: h_backward = k_backward × PWM + b_backward
3. 回差 = mean(|h_forward - h_backward|) 在各 PWM 点的偏差
4. 线性系数 k = (k_forward + k_backward) / 2，写入固件
```

> 齿轮齿条理论映射：Δh = r × θ = r × (270°/PWM_range) × PWM。其中 r 为齿轮分度圆半径，实测拟合的 k 应与理论值一致（偏差 <5%），若偏差过大说明齿轮模数选型有误或啮合不良。

#### 3.5.1 实测结果（2026-07-30）

**测试方法**：舵机从中位 135° 出发，按 +2°、+8°、+15°、-15°、-8°、-2° 序列步进，每步用卡尺测量齿条顶端高度。对称序列使去程和回程经过相同的总偏角（25°），直接检验回差。

**测试代码**：`app/app_test.c`，OLED 实时显示当前舵机角度和理论齿条位移。按键触发步进。

**原始数据**（卡尺读数，mm）：

| 序号 | 动作 | 舵机角 θ | 齿条高度 | Δh（从中位） |
|------|------|----------|----------|-------------|
| 0 | 初始（中位） | 135° | 22.5 | 0.0 |
| 1 | CCW +2° | 133° | 23.0 | +0.5 |
| 2 | CCW +8° | 125° | 25.4 | +2.9 |
| 3 | CCW +15° | 110° | 29.3 | +6.8 |
| 4 | CW 15° | 125° | 25.4 | +2.9 |
| 5 | CW 8° | 133° | 23.0 | +0.5 |
| 6 | CW 2° | 135° | 22.5 | 0.0 |

**分析**：

| 舵机偏角 \|Δθ\| | Δh 理论 (mm) | Δh 实测 (mm) | 偏差 |
|----------------|--------------|-------------|------|
| 2° | 0.545 | 0.5 | -0.045 |
| 10° | 2.727 | 2.9 | +0.173 |
| 25° | 6.818 | 6.8 | -0.018 |

- 最小二乘拟合：**k = 0.274 mm/deg**（理论值 0.273，偏差 +0.6%）
- **回差**：正反行程在 10° 偏角处齿条高度均为 25.4mm，在 2° 处均为 23.0mm → **回差 ≈ 0**（卡尺分辨率内不可测）
- 2° 处 0.045mm 偏差为卡尺精度极限（±0.05mm），非系统误差

**结论**：

1. 齿轮齿条线性度极好，理论映射直接可用，固件系数无需修正
2. 重力预紧完全消除齿轮-齿条啮合回差，正反转同一 PWM 给出同一齿条高度
3. 对小球脉冲控制的含义：**两个方向单脉冲位移对称**，`PULSES_TO_P5` 标定后正反通用，无需方向补偿

| \|error\| | KP | KD | KD/KP | 转弯半径 R |
|-----------|------|------|--------|-----------|
| 0 | 0.0080 | 0.0047 | 0.59 | ∞ (直行) |
| 1 | 0.0120 | 0.0061 | 0.51 | 3.06m |

| 6 | 0.0180 | 0.0077 | 0.43 | 0.34m |
| 7 | 0.0161 | 0.0077 | 0.48 | 0.33m |

> **算法流程：**
>
> 1. 加权平均：`error = Σ(w[i] × sensor[i]) / Σ(sensor[i])`，范围 -7..+7
> 2. Slew rate filter：误差变化每 tick 限幅 ±5，平滑入弯跳变
> 3. `correction = KP[|error|] × error + KD[|error|] × d(error)/dt`
> 4. Correction clamp：`|correction| ≤ base_speed` 防止内侧轮反转
> 5. 差速输出：`left = base_speed + correction`, `right = base_speed - correction`
>
> 转弯半径（稳态）：`R = base_speed × track / (2 × KP × |error|) = 0.0735 / (2 × KP × |error|)`

**丢线行为：**
- 全白 (sum=0) → 向 `s_last_valid_error` 方向搜索，cap 限幅 ±6
- 全黑 (sum=8) → 直行（十字路口策略）

### 舵机 PWM 控制原理

S20F 是 270° 数码舵机，通过 PWM 脉冲宽度控制输出轴角度，映射关系为**线性**：

```
pulse_us = 500 + angle_deg × 2000 / 270
```

| 脉冲宽度 | 舵机角度 | 说明 |
|----------|----------|------|
| 500 µs | 0° | 最小极限 |
| 1167 µs | 90° | |
| 1500 µs | 135° | **中位（初始位置）** |
| 2167 µs | 225° | = 135° + 90° |
| 2500 µs | 270° | 最大极限 |

- PWM 频率 50Hz（周期 20ms），控制信号为周期内高电平脉冲宽度。
- 舵机内部自带位置闭环，收到有效脉冲后主动锁位，输出轴在无外力下**转不动**（保持力矩作用）。
- 通电保持位置时有轻微"滋滋"电流声，为数字舵机正常现象（内部 200-300Hz PID 控制回路）。
- 实测验证：初始位置 135° → 设 90°（1167µs），舵机旋转 45° 到达 90° 位置。

#### 四级运动学链

##### 第 1 级：PWM → 舵机角度

```
θ_servo = (PWM_us - 500) / 2000 × 270° = (PWM_us - 500) × 0.135  °/μs
```

反向：

```
PWM_us = 500 + θ_servo × 2000/270 = 500 + θ_servo × 7.407  μs/°
```

| 指标 | 值 |
|------|-----|
| 1 PWM 步对应舵机角 | 0.135°/步 |

| MSPM0 分辨率 | 远优于舵机本身精度（舵机是精度瓶颈） |

##### 第 2 级：舵机角度 → 齿条竖直位移

齿轮纯滚动，齿条位移与舵机转角严格线性。摆杆自重始终压在齿条顶端，齿轮-齿条啮合间隙被单向受力消除，无回差：

```
h = r × θ_servo(rad)
  = 15.625 × θ_servo(deg) × π/180
  = 0.2727 × θ_servo(deg)  [mm]
```

| θ_servo | h (mm) |
|---------|--------|

##### 第 3 级：齿条位移 → 摆杆倾角

摆杆左端合页铰链固定为唯一支点，右端齿条顶端竖直顶升：

```
tan(φ) = h / L                      （精确公式）
φ(rad) ≈ h / L                       （小角度近似，φ < 10° 时误差 <1%）
φ(deg) = h/L × 180/π = 57.30 × h/L
```

代入 h = 0.2727 × θ_servo：

```
φ(deg) = 15.625 × θ_servo(deg) / L(mm)
```

**机械减速比** = L / 15.625。以 L = 244mm 为例，减速比 **15.6:1**（舵机转 15.6° 摆杆偏 1°）。

##### 舵机偏角 → 管道倾角 换算速查

> **符号约定**：管道倾角 φ **上倾为正**（右端抬高 → 球向 -cm）、**下倾为负**（右端降低 → 球向 +cm）。

#### 关键结论

1. **大减速比容忍舵机误差**：L=244mm 时减速比 15.6:1，舵机 0.54° 误差仅导致摆杆倾角 0.035°、加速度扰动 0.0059 m/s²，完全可接受。

2. **舵机工作范围远小于满量程**：产生 0.1 m/s² 回复加速度仅需舵机偏转约 9.1°（摆杆倾角约 0.58°）。舵机绝大部分时间在中位 135°±9.1° 内工作，仅用了满量程 270° 的约 7%。

3. **弯道离心力是最大扰动源**：v=0.42m/s, R=0.5m 时离心加速度 0.353 m/s²，需补偿舵机偏转约 32.2°，仍在可用范围内。

4. **二级公式（直接跳过硬计算）**：

```
PWM = 1500 + φ_des(deg) × 116
    = 1500 + φ_des(rad) × 244 × 27.2
```

> 推导（φ 上倾为正、下倾为负）：Δθ = +L × φ / 15.625 = +15.6 × φ(deg)。PWM = 1500 + Δθ × 2000/270 = 1500 + φ × 244 × 2000 / (15.625 × 270) = 1500 + φ × 115.7 ≈ 1500 + φ × 116

#### 控制架构

```
K230球坐标 → error_x(cm) → 外环位置PID → φ_des(期望倾角)
    ├─ KP_ball × error              (比例)
    ├─ KD_ball × Δerror / Δt         (微分)
    ├─ Kff_accel × Δv_car / Δt       (车体加速度前馈)
    └─ Kff_curve × sgn(line_error)   (弯道离心力前馈)
         ↓
φ_des → PWM = 1500 - φ(deg) × L / 2.11  →  内环速率限幅  →  BSP_Servo_SetPWM
```

内环速率限幅（防急动）：每次限幅 3~5 PWM 步/10ms。

> **算法流程：**
>
> 1. 加权平均：`error = Σ(w[i] × sensor[i]) / Σ(sensor[i])`，范围 -7..+7
> 2. Slew rate filter：误差变化每 tick 限幅 ±5，平滑入弯跳变
> 3. `correction = KP[|error|] × error + KD[|error|] × d(error)/dt`
> 4. Correction clamp：`|correction| ≤ base_speed` 防止内侧轮反转
> 5. 差速输出：`left = base_speed + correction`, `right = base_speed - correction`
>
> 转弯半径（稳态）：`R = base_speed × track / (2 × KP × |error|) = 0.0735 / (2 × KP × |error|)`

**丢线行为：**
- 全白 (sum=0) → 向 `s_last_valid_error` 方向搜索，cap 限幅 ±6
- 全黑 (sum=8) → 直行（十字路口策略）

#### 方向约定（实测） {#方向约定实测}

> **这是舵机控制的唯一权威方向表（2026-07-30 实测标定）。**

> **倾角符号约定**：φ > 0 为上倾（右端抬高），φ < 0 为下倾（右端下沉）。φ > 0 时球向 -cm 方向加速，φ < 0 时球向 +cm 方向加速。

#### K230 视觉闭环：舵机修正方向公式 {#k230-修正公式}

> **这是 K230 位置→舵机修正的权威公式，AI 写视觉闭环控制代码时必须逐字遵循，不得自行推导符号。**

K230 位置坐标与水管坐标系**一致**：+mm = 球在 +cm 方向，-mm = 球在 -cm 方向（即与实测方向表中"球运动"列的符号相同）。

```
error_mm = target_mm - pos_mm         // pos_mm 来自 MID_K230_GetPosition()
correction_deg = KP * error_mm         // KP 必须为负值，见下方推导
servo_offset += correction_deg         // 增量累加 = 积分作用
```

**KP 符号推导**（AI 必须理解，不可跳步）：

设 target = -50mm，当前 pos = -60mm（球偏右，未达目标）：
- error = -50 - (-60) = **+10mm**（正误差 = 球偏右，需向左/正方向移动）
- 球 → +cm 需要 CCW → 需要 **负 offset**
- 所以 correction 必须为负：KP × (+10) < 0 → **KP < 0**

设 target = -50mm，当前 pos = -40mm（球偏左，过冲）：
- error = -50 - (-40) = **-10mm**（负误差 = 球偏左，需向右/负方向移动）
- 球 → -cm 需要 CW → 需要 **正 offset**
- 所以 correction 必须为正：KP × (-10) > 0 → **KP < 0** ✓ 一致

**结论：KP 恒为负值。** 对应代码中 `SETTLE_VIS_KP_DEG_PER_MM = -0.5f`。

> **🚫 常见 AI 错误**：AI 常写出 `correction = KP * error` 并设 KP 为正值，导致 servo 修正方向相反、球远离目标而非趋近。这是 2026-07-30 实测中两次出现过的 bug。**如果代码中 KP 是正值，correction 公式必须是 `correction = -KP * error`。两种写法等价，但不可混用。**

### 静止平衡（Q3 纯视觉闭环 PID）

> **方案迭代（2026-07-30）**：开环 bang-bang 方案（上方）已替换为纯视觉闭环 PID。新方案不再使用开环时序脉冲，全程由 K230 位置反馈驱动 PD 控制。状态机保留 IDLE → TO_P5 → TO_M5 → DONE 结构。

#### 控制策略

纯视觉 PD 闭环，无开环基角。PID 输出直接叠加在中位 135° 上：

```
K230 位置 → error = target - pos (mm)
         → P = KP × error
         → D = KD × (-vel)          微分先行，vel 由 K230 位置差分
         → trim = P + D + I          clamped to ±PID_CLAMP_DEG
         → servo = 135° + trim
```

**关键实现细节**：

1. **K230 坐标符号反转**：K230 端 `cx_to_mm()` 输出正负号与物理坐标系相反。`mid_k230.c` 解析时取反（`s_ball_position = -pos`），`MID_K230_GetPosition()` 返回已修正的物理坐标。详见 [2.8 节](#28-k230--mspm0-通信协议)。

2. **速度持久化（100Hz vs 33Hz 帧率差修复）**：K230 约 33fps，但 PID 控制跑 100Hz。两帧之间 `pos` 不变，若每 tick 重新计算 `vel = (pos - prev_pos) / dt` 则 2/3 的 tick 速度为 0 → D 项失效。**修复**：新帧到达时更新速度并存入 `s_ball_velocity`，同帧重复 tick 保持上一次速度不变。等效 D 增益比未修复版强约 3×。

3. **微分先行（derivative-on-measurement）**：D 项仅作用于测量值（`-vel`），避免目标切换时设定值跳变引起微分冲击。

4. **积分分离 + 抗饱和**：仅 `|error| < VISION_I_ERR_THR` 时累积积分，限幅 ±VISION_I_MAX。

### 水管非理想性问题与对策 (2026-07-30)

**问题描述**：切成一半的四分 PPR 水管并非完全笔直，存在微小的形变扭曲（肉眼不明显）。导致两个后果：

1. **不存在统一的"水平位"**：球在管道不同位置时，使其静止所需的舵机角度不同。局部低洼处球会陷进去出不来。
2. **摩擦系数空间分布不均**：不同区域的管壁粗糙度不同，静摩擦死区随位置变化，单点测量无代表性。

**结论**：3.2 节"静摩擦死区测试"意义不大，不再作为标定步骤执行。

**解决方案（按推荐优先级）**：

| 方案 | 名称 | 原理 | K230 依赖 | 备注 |
|------|------|------|-----------|------|
| **一** | **位置相关水平标定表** | 逐位置（-12~+12cm，步长 1~2cm）标定使球静止的舵机角度，做成 `neutral_angle[ball_pos_cm]` 查找表。控制时 `φ_des = neutral_angle[pos] + PID_output`，管道扭曲和摩擦不均被标定表一次性吸收 | 自动化需 K230 | 手动逐点放球不可行（手指离开扰动破坏状态），自动化版本：舵机大角度把球运到尽头 → 缓慢回扫 → K230 检测球开始滚动的临界角，球始终在管道内，无接触扰动 |
| **二** | **Dither 高频微振** | 舵机输出叠加高频小幅正弦振荡（幅度 ~0.5°~1°，频率 10~20Hz），打破静摩擦，使等效摩擦力均匀化。经典精密机械定位技巧 | 无 | 代价：舵机持续微动有声 |
| **三** | **K230 视觉闭环 + 积分抗饱和** | 积分项自然补偿局部静摩擦：球卡住 → error 持续 → 积分累积 → 倾角增大 → 克服摩擦。配合保守的积分限幅 + anti-windup | **是** | 微分先行 PID（derivative-on-measurement），积分分离（小误差区积分缓增克服静摩擦） |

**建议组合**：上电后跑方案一的自动化标定（需 K230），运行中用方案二（dither）+ 方案三（视觉闭环 + 积分补偿）并行。

### 注意事项

1. **互斥原则**：同一时间只能使用一个循线模块。两个模块的函数都会编译链接，但 `main.c` 只调用其中一个。若 `#include` 了两个头文件但只调用一个模块的函数，另一个模块的代码虽然链接了但不会被调用——浪费 Flash 空间，建议注释掉不用的 `#include`。

2. **命名规律**：所有 app 模块遵循统一的回调接口命名模式：
   - `<前缀>_Init()` — 初始化
   - `<前缀>_TimerTick()` — 10ms 定时器回调
   - `<前缀>_Run()` — 主循环调用
   - `<前缀>_Start()` / `_Stop()` / `_IsRunning()` — 按键控制

3. **app_control 不变**：`app_control.c`（速度 PI + BLE 指令）是独立模块，与循线模块无关，切换时不需要改动。

4. **MID_LineTrack 共用**：两个循线模块都依赖 `middleware/mid_line_track.c` 提供底层灰度 PD 计算，切换时 middleware 层完全不动。

5. **Keil Group 管理**：新增的 `.c` 文件加入 Keil 项目后无需频繁移除。由 `main.c` 的实际调用决定哪个模块参与运行，未调用的模块仅占用少量 Flash 空间。

6. **OLED 显示差异**：不同模块的 OLED 布局不同（高速循线显示速度曲线，慢速直行显示距离+目标速度），切换后留意显示是否与预期一致。

7. **小球控制 ↔ 循线模块互切**：两类模块依赖的硬件不同——
   - 循线模块依赖电机、编码器、灰度传感器、MID_LineTrack
   - 小球控制模块仅依赖舵机（BSP_Servo）
   - 切换时 `main.c` 的 7 处替换规则不变，但 **`BSP_Servo_Init()` 必须在 `main()` 中保留**（目前已保留），否则小球控制模块上电后舵机无 PWM 输出
   - 小球控制模块切换到循线模块后，舵机保持中位 135°（摆杆水平），不影响循线运行
